# ADR-0001. Модульный монолит и отдельный публичный контур

- Статус: принято
- Дата: 03.11.2026

## Контекст

Модуль ставится на серверы организации (on-premise), внедрение — 2–4 недели, одна установка обслуживает одну организацию. Команда — 3–4 разработчика. Из интернета должны быть доступны только страница должника и API мобильного приложения (ТЗ, раздел 9).

## Решение

- Бэкенд — модульный монолит: один solution, модули с явными границами (`*.Contracts` / `*.Module`), правило зависимостей проверяется ArchUnitNET.
- Три хоста из одной кодовой базы: `Api` (внутренняя сеть), `Worker` (фоновые задачи), `PublicGateway` (DMZ, без прямого доступа к БД — только узкий API ядра).
- Мультитенантности нет.

## Последствия

- Меньше компонентов для установки и сопровождения у клиента.
- Модули можно вынести в отдельные сервисы позже, если понадобится масштабирование.
- Нужна дисциплина границ: обращения в обход `*.Contracts` ломают сборку тестами.
