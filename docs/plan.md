## 2. Стек

**Бэкенд (.NET 10):**

| Слой | Выбор |
|---|---|
| Хосты | `Api` (веб сотрудников + SignalR), `Worker` (фоновые задачи), `PublicGateway` (DMZ) |
| Доступ к данным | EF Core 10 + Npgsql для обычных операций; Dapper и чистый SQL для пересчёта и отчётов; `NpgsqlBinaryImporter` (COPY) для импорта |

| Реалтайм | SignalR: новая оплата на открытой карточке, состояние звонка, уведомления |
| Вход и права | Cookie-аутентификация, policy-based authorization (вкладка × уровень), централизованный фильтр видимости дел; AD/LDAP — этап 3 |
| Валидация | FluentValidation |
| Шифрование ПДн | `AesGcm` + слепой индекс `HMACSHA256` для поиска по ИНН/телефону; value converters EF |
| Интеграция с АБС | HttpClient + Polly (REST), `System.ServiceModel.Http` (SOAP), SSH.NET (SFTP), CsvHelper / ExcelDataReader |
| Отчёты | MiniExcel (потоковая запись); PDF — HTML-шаблон → Chromium (Playwright) |
| Юр. документы | Шаблоны .docx (MiniWord / Open XML SDK) |
| Телефония | Свой тонкий клиент ARI (REST + WebSocket) |
| Наблюдаемость | Serilog, OpenTelemetry → Prometheus / Grafana / Loki |
| Тесты | xUnit, Testcontainers (PostgreSQL), ArchUnitNET |

Не используем из-за коммерческих лицензий: MediatR, AutoMapper, MassTransit (платные с 2025), QuestPDF (бесплатен до $1 млн выручки), PrimeVue 5+ (PrimeUI License).

**Фронт:** Vue 3.5 (`<script setup>`), TypeScript, Vite, Vue Router, Pinia, TanStack Query for Vue + клиент из OpenAPI (orval), PrimeVue 4.5.5 с пресетом токенов «ЛБ Ломбард», VeeValidate + zod, vue-i18n (ky/ru), vue-echarts, `@microsoft/signalr`, JsSIP (софтфон), Vitest + Playwright.

**Страница должника (Э-13):** отдельная сборка Vue без UI-библиотеки, бюджет — открытие до 3 с на мобильном интернете.

## 3. Модули бэкенда

```
Identity      — вход, SMS-код, сессии, блокировки, позже AD/LDAP
Access        — матрица роль×вкладка, видимость дел (роль×филиал×стадия), маскирование
Integration   — адаптеры АБС, staging → проверка → upsert, «Разобрать», outbox в АБС, ночная сверка
Core          — клиент, договор, график, снимки задолженности, платежи, дело, периоды просрочки
Recalc        — ночной пересчёт: дни просрочки, стадии, сборка дел, назначение, очереди
Strategy      — версии стратегий, сегменты, шаги, A/B
ContactGuard  — ЕДИНАЯ проверка перед касанием: свежая оплата, лимиты, часы, праздники,
                «только письменно», пауза, договор у юриста
Comms         — журнал коммуникаций, SMS, звонки, автообзвон, стоимость, баланс «через нас»
Promises      — обещания и их статусы, атрибуция платежей касаниям
Requests      — заявки на реструктуризацию, согласования
Legal         — юридические дела, этапы, документы, напоминания
Reporting     — асинхронные отчёты, рассылка по расписанию
Audit         — журнал только на добавление
Public        — ссылки оплаты, страница должника, API мобильного приложения
```

Каждый модуль — пара проектов `*.Contracts` (публичный API) и `*.Module` (internal-реализация). Модуль обращается к другому только через `*.Contracts`; правило проверяет `Architecture.Tests`.

## 4. Технические решения, которые закладываем сразу

- **Шифрование + поиск.** ИНН, телефоны, адреса и записи разговоров зашифрованы; поиск — по слепому индексу (HMAC). Иначе «поиск до 1 с» не выполнить.
- **Маскирование** — на слое сериализации по правам роли; одинаково в UI, выгрузках, отчётах и журнале.
- **ContactGuard — единственная точка входа** для любого касания: автоматического, ручного, автообзвона, визита.
- **Ночной пересчёт — пакетным SQL**, цель ≤ 30 минут на 500 тыс. договоров. Снимки задолженности (около 180 млн строк в год) секционированы по месяцам с первого дня.
- **Журнал аудита**: триггер запрещает UPDATE/DELETE, у приложения нет на это прав, записи сцеплены хэшами, таблица секционирована по месяцам (поиск за месяц ≤ 5 с).
- **Обмен с АБС** идемпотентный по ID записи в АБС; ошибочные записи — в карантин «Разобрать»; исходящие — через outbox.
- **Время и деньги**: часовой пояс организации (по умолчанию Asia/Bishkek); суммы `numeric(18,2)` + валюта, сом и доллар никогда не складываются.
- **Права** — централизованный сервис видимости дел + отдельный набор тестов на матрицу.

## 5. Звонки и SMS

- **Звонок коллектора (MVP):** браузер (JsSIP, WSS) → Asterisk (PJSIP + WebRTC) → SIP-транк оператора. Бэкенд через ARI проверяет ContactGuard, запускает вызов, проигрывает фразу о записи на языке клиента, пишет разговор (MixMonitor) и привязывает запись к касанию. Если телефония недоступна, результат отмечается вручную.
- **Автообзвон и робот (этап 2):** модуль на ARI. Суммы и даты собираются из заранее записанных фрагментов на ky/ru: качественного синтеза кыргызской речи нет.
- **SMS:** местный агрегатор по HTTP API, статусы доставки, стоимость; счётчик сегментов для кириллицы (70 символов, в склейке 67). Имя отправителя регистрируется у операторов неделями — заявку подаём на этапе 0.
- **Режим «через нас»** (этап 2) — баланс, тарифы с наценкой, порог, остановка платных касаний; сначала ответ юриста о лицензии на связь.

## 8. Вопросы к ТЗ

1. Озвучка сумм на кыргызском в голосовом роботе: синтез или записанные фрагменты? Влияет на оценку этапа 2.
2. Срок хранения снимков задолженности (по снимку на договор в день) в разделе 4.5 не указан.
3. Отправка обещаний в АБС через файловый адаптер в MVP: в каком формате АБС их принимает и кто дорабатывает её сторону?
4. Атрибуция платежа («3 дня после касания»): как считать, если в эти дни были и SMS, и звонок, а платёж частичный? Нужен пример в ТЗ.
5. API мобильного приложения должен стоять в DMZ уже в MVP? В разделе 10 мобильного приложения нет, а раздел 9 открывает его API наружу.
